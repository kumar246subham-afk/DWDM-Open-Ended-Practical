Practical 4: Data Preprocessing Using a Sample Dataset

Aim

To understand the importance of data preprocessing by identifying missing values, duplicate records, inconsistent values, invalid data, and categorical variables requiring encoding, and transforming a raw dataset into a clean, model-ready dataset suitable for data mining.

Learning Outcomes

After completing this practical, students will be able to:

  • Understand why data preprocessing is required before applying data mining techniques.
  • Identify missing values and duplicate records systematically in tabular datasets.
  • Detect inconsistent, dirty, and invalid data out of logical constraints.
  • Perform robust data cleaning, imputation, and standardization.
  • Encode categorical variables into numeric form using Label Encoding and One-Hot Encoding.
  • Identify the independent and dependent variables and justify technical feature selection.
  • Prepare a comprehensive, model-ready dataset suitable for machine learning and data mining algorithms.

Introduction

Real-world datasets are rarely perfect. They frequently contain missing values, duplicate records, inconsistent formats, incorrect entries, and text-based categorical columns. Before executing Extract-Transform-Load (ETL) pipelines, data warehousing, or data mining algorithms, the data must be rigorously cleaned, standardized, and converted entirely into numeric form to prevent model bias and calculation failures.

PROBLEMS & TECHNIQUES

Problems Identified in the Dataset

Problem Example Reason
Missing Value CGPA = NA, Attendance = NULL Algorithms cannot process incomplete data reliably; causes mathematical crashes in linear/distance calculations.
Duplicate Record S101 and S106 Duplicates produce biased analysis and falsely inflate pattern weights in data mining.
Inconsistent Values Male, Female, M, F Values should follow one standard; algorithms treat 'M' and 'Male' as two distinct categories.
Invalid Age -5 Age cannot be negative in the physical world; violates logical integrity constraints.
Invalid CGPA 15.2 CGPA should be bounded strictly between 0 and 10 according to academic evaluation scale.
Invalid Attendance 120 Attendance cannot exceed 100%; reflects typographical entry errors.
Missing Department NULL Department is required for academic analysis and department-wise stratification.
Missing Phone NULL Incomplete contact information; represents missing communication metadata.
Categorical Text Values Gender, Department, City, Placement stored as text Most data mining and ML algorithms require numeric input matrices, not string literals.

Techniques Used

Each problem identified above is solved using one specific, named technique:

Technique Used Description (1–2 lines)
Mean / Median Imputation Replaces a missing numeric value with the column's mean or median, keeping the overall distribution roughly unchanged.
Mode Imputation Replaces a missing categorical value with the most frequently occurring category in that column.
Duplicate Removal Detects rows that are exact repeats of another row and deletes the extra copies, keeping only one unique entity.
Data Standardization (Text) Converts inconsistent text values (e.g., M/F) into one consistent standard form (Male/Female).
Range / Validity Check Verifies a value falls within a logically possible range (e.g., Age > 0, 0–10 CGPA, Attendance ≤ 100%) and corrects violations.
Label Encoding Converts a binary categorical column (2 values only) into a single 0/1 numeric column.
One-Hot Encoding Converts a nominal categorical column (more than 2 values, no order) into multiple binary (0/1) columns, one per category.

Data Preprocessing Steps (Cleaning Phase)

Step 1 — Handle Missing Values: Replace NA/NULL with suitable values such as mean, mode, or a verified value looked up from the source system (e.g. CGPA NA → 8.3, Attendance NULL → 90, Department NULL → Mode CSE).

Step 2 — Remove Duplicate Records: Delete repeated records after verifying they refer to the same entity (e.g. S101 and S106 refer to the exact same student Arun Kumar; S106 is dropped).

Step 3 — Standardize Gender: Convert M → Male and F → Female so that all text records adhere to uniform category naming standards.

Step 4 — Correct Invalid Age: Replace negative age (-5) with the correct, verified age (20), preserving physical validity.

Step 5 — Correct Invalid CGPA: Replace values outside the valid 0–10 range (15.2) with the correct, verified value (9.2).

Step 6 — Correct Attendance: Replace values greater than 100% (120) with the maximum boundary or verified record (100%).

ENCODING STRATEGY

Step 7 — Encode Categorical Variables

After cleaning, every remaining text column must be converted into numbers before the dataset can be ingested by a data mining or machine learning algorithm. Two different techniques are used depending on whether the category has an inherent mathematical order:

  • Label Encoding: Used for binary columns with only two possible values (Gender, Placement). Each category is assigned 0 or 1.
  • One-Hot Encoding: Used for nominal columns with more than two values and no natural order (Department, City). A separate binary (0/1) column is created for each category, preventing the algorithm from mistakenly assuming one category is "greater" than another (e.g. CSE < IT < AI < DS).

Categorical Variable Encoding Table

Column Category Type Technique Used Why This Technique
Gender Binary (Male/Female) Label Encoding (Male=0, Female=1) Only 2 categories — a single 0/1 column is enough, no ranking is implied.
Placement Binary (Yes/No) Label Encoding (No=0, Yes=1) This is the target column — binary outcomes are simply mapped to 0/1.
Department Nominal (CSE, IT, AI, DS) One-Hot Encoding No natural order between departments — label encoding would wrongly imply CSE < IT < AI < DS.
City Nominal (Ahmedabad, Surat, Rajkot, Vadodara) One-Hot Encoding Cities have no natural order — one binary column is created per city instead.

Feature Selection: Independent and Dependent Variables

Not every column in the cleaned dataset should be fed into a model. The table below identifies column roles with justifications:

Column Role Justification
AgeIndependent variableReflects maturity/work-readiness; a plausible factor in employability.
CGPAIndependent variableDirect measure of academic performance — typically the strongest predictor of placement.
AttendanceIndependent variableReflects discipline and engagement, which recruiters associate with employability.
GenderIndependent variableIncluded to check for and analyse any bias in placement outcomes; must be used ethically.
DepartmentIndependent variableDifferent departments can have different industry demand and placement rates.
CityIndependent variableMay reflect proximity to companies or campus recruitment activity.
PlacementDependent variable (target)This is the outcome the data mining model is being built to predict (Binary: 0 or 1).
Student_IDDropped — not a featureA unique identifier with no predictive meaning; using it would let a model “memorize” rows.

Conclusion & Key Learnings

Conclusion: In this practical, a raw, real-world educational dataset containing missing values, duplicates, invalid negative age, out-of-range CGPA/attendance, and non-numeric text columns was systematically engineered. Through targeted imputation (Mean for CGPA, Mode for Department), text standardization, duplicate removal, Label Encoding (Gender, Placement), One-Hot Encoding (Department, City), and ethical feature selection, the dataset was transformed into a clean, 100% numeric model-ready format ready for machine learning algorithms.
